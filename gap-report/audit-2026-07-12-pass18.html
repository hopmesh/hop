Findings

Most-severe first. Each was runtime-verified by a finder, then independently re-verified with a fixture or revert before the fix landed.
F-CI-1 critThe branch-protection audit PR #85 "fixed" was a broken workflow file, 0 jobs, all sessionfixed #97
Vector
administration is not a valid GitHub Actions permissions: scope (actionlint: "unknown permission scope"). GitHub rejected the whole workflow file, so every run since #85 ran ZERO jobs and failed in 0s. Before #85 the job at least ran and surfaced the real cause (HTTP 403). So #85 diagnosed correctly but implemented with a key that can never work, silently disabling the drift-detector the whole session. The default GITHUB_TOKEN genuinely cannot read branch protection (needs repo-admin, which that scope does not grant).
Fix
Remove the invalid key (file valid + runs again); run the live assertion ONLY with a real BRANCH_PROTECTION_TOKEN PAT, else skip with an actionable notice (honest-green, not a false red). The PAT has since been seeded and verified (administration:read, HTTP 200); the audit now runs the real check and passes. Protection on main was correct throughout (9 raw contexts).
F-18a highThe F-7 rate cap's map was unbounded, the anti-DoS cap was itself a memory-exhaustion DoSfixed #96
Vector
The map's sweep only evicted STALE entries. An attacker minting fresh authenticated identities (one Data frame each, then disconnect, all in one window) grew peer_rates without bound on the 2 GiB relayd instance. Reproduced: the map grew to 25 000 with no ceiling.
Fix
A hard MAX_PEER_RATE_KEYS=20_000 ceiling that force-evicts the oldest windows by EXACT count (so it still bounds when every entry shares one start_ms, the actual attack). Revert-proof test: without the eviction the map hits 25 000; with it, bounded at 20 000.
F-CI-2 highA YAML-anchor-defined job was invisible to the deploy-gate allowlist guardfixed #98
Vector
The job-boundary regex required the line to end right after the colon (:\s*$), so a job written sneaky: &anchor (or inline map) was never seen as a job at all: it could run in CI, produce a required check-run, and never be required by the deploy gate, defeating the very nameless-job guard #79 added.
Fix
Match :(\s|$) in both check-required-checks.sh and check-branch-protection.sh so any anchor/inline job is seen (then flagged nameless if it has no name:, fail-loud not fail-open). Self-test grew with anchor-visible + anchor-hole cases.
F-web-1 highThe F-3 pkg-fresh guard silently passed when a committed pkg file went untracked at HEADfixed #100
Vector
Both the interface diff and the wire-stamp check conflated "not in a git tree" (legit tarball fallback) with "in a git tree but git show HEAD:sim/pkg/$f failed" (should be hard failure). Since build-wasm.sh overwrites the working tree just before the guard, an untracked committed file fell back to comparing a fresh build against itself and reported "fresh", even across a real wire bump. Reproduced end-to-end.
Fix
Determine in_git once; inside a git tree a committed pkg file or stamp missing from HEAD is DRIFT (not a fallback trigger). Verified: the reproduced untracked-stamp case now exits 1 with a precise message.
F-18b highThe pre-auth rate budget reset on every reconnect (the unauthenticated attacker)fixed #96
Vector
Pre-handshake frames were keyed per-LINK, and link ids are ever-incrementing, so an attacker who NEVER authenticates (exactly relayd's threat model behind the LB) got a fresh 300-frame budget on every reconnect.
Fix
Collapse all pre-auth traffic into one shared PeerRateKey::PreAuth bucket with its own larger budget (3 000, generous so a burst of legit peers handshaking after a restart is not starved). A reconnect can no longer dodge the cap, and pre-auth no longer churns the map.
F-1 medHopStatus.forwardHops was still a signed Byte, the sibling the F-9 fix missedfixed #99
Vector + fix
Same uint8_t-renders-negative overflow F-9 fixed for HopMessage.hops, just reached via status(id) instead of pollInbox. Changed to UByte. F-2: F-9's own >= 0u check is now tautological; added a real reinterpretation test (native 200 marshals via Byte -56 and must read 200u) for both fields.
F-CI-3 / F-CI-4 meddocs-guard missed no-semicolon entities and the lookalike dashes U+2015 / U+2012fixed #98
Vector + fix
The encoded scan required a trailing ;, but &#8212 (no semicolon) still renders an em-dash; made the ; optional. And only em/en were banned, so the near-identical horizontal bar (U+2015) and figure dash (U+2012) sailed through, both now banned in every form. Self-test grew 27 to 35 cases.
crypto lowhps::verify_publish used non-strict ed25519 (malleable signatures)fixed #95
Vector + fix
Channel/service broadcast signatures used verify where the rest of the crate uses verify_strict. Non-strict admits a cofactored second S, so a keyless attacker could mint a different valid-looking signature for the same message. Switched to strict (a superset that never rejects a canonical sig). Pre-existing, not a migration regression.
F-CI-5 / F-CI-6 lowdocs-guard BT-identifier exclusion too broad; a matrix-templated job name would rubber-stampfixed #98
Vector + fix
The open-ended BT-hyphen exclusion spared bare hyphenated marketing uses of the word; narrowed to the two real iOS background-mode identifiers (the central / peripheral forms). And a ${{ matrix.os }} job name can never match a real check-run name, so the deploy gate would poll forever; the parser now rejects a templated name (exit 8).
F-18c lowpeer_rate_key is O(live links), its doc comment claimed O(1)fixed #96
Fix
Corrected the comment: the scan is inherent to relayd's position below the core transport seam (it learns a link's address only by querying node.peer_links), runs on the frame-bounded driver thread, and only for frames that pass the length cap.
Flagged, not fixed this pass (latent / non-blocking). F-18d: guard_core is coarse-grained, a panic mid-arm can leave Node bookkeeping half-applied. Memory-safe (plain safe-Rust maps, so AssertUnwindSafe is sound), systemic to all three services, no reachable panic found beyond the already-fixed hexd, worth a dedicated exception-safety pass. F-3 (Android): bearer-lan coverage wobbles ~1 line run-to-run (94.4 to 94.8%), well above the 80% floor, a timing-sensitive path worth root-causing before its margin narrows. F-CI-7: the HopDriver per-file coverage awk's NF-3 column offset is correct today but not pinned against a future llvm-cov column-layout change. F-web-2: PR #88's commit message overstates Astro 7's Node floor (astro@7.0.7 actually allows Node 18/20); immutable history, cosmetic.
