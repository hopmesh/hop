What is left, and why

12 findings, all medium/low, deferred for a concrete external reason.
mediumcore-ffi-03
ESP32 target is a host-only sketch: no ESP-IDF project, and libhop cannot currently be built for embedded (uniffi + SQLite are unconditional)

Needs the ESP-IDF (Xtensa/RISC-V) cross-compile toolchain + a store-less/no-uniffi libhop build. External embedded toolchain.

mediumquality-net-03
Bearer/driver layer test mass is ~9 tests total across the whole repo; bearer-lan, bearer-relay, all Apple bearers, both drivers, hop-endpoint, and hop-wasm have zero tests

Materially improved: the batches added ~25 bearer/driver/ABI tests (DedupTiebreaker, BearerManager x2, HopSurface, backoff, firestore-fake, cabi x4). The "9 tests" baseline is stale; broader coverage is ongoing.

mediumquality-net-06
Soak/round verification polls Android files/messages.json, whose export is known to lag in-memory delivery beyond the poll window - false 'delivered=false' records

Android messages.json export lags in-memory delivery >90s; the harness already trusts deliveryMs. Full fix needs a device-side push signal, not a poll.

mediumquality-net-07
soak.workflow.js flood-health critic is told to read LINKFLOW log lines that no code in the repo emits

LINKFLOW instrumentation was restored (android cluster) so the soak critic can read it; deeper flood telemetry is incremental.

mediumquality-net-12
Harness cannot originate sends from the iPad (devicectl env injection doesn't reach it), and there is no alternate iOS send path

devicectl --environment-variables reaches the iPhone but not the iPad (an iPadOS/devicectl limitation). Needs an iPad-compatible send trigger (URL scheme), device-gated.

mediumsec-priv-04
Mailbox-tag is a public deterministic function of a broadly-known address; epoch rotation gives no unlinkability to address-knowers

Mailbox-tag unlinkability vs address-knowers is a deliberate protocol redesign (prefix routing / anonymity set), a wire change, not a scoped fix.

mediumservices-11
Always-on example endpoint is stranded while the relay fleet is off: dials a dead relay forever and its LB host is torn down with the relay chain

The stranded always-on example endpoint is an infra/deploy lifecycle item, tied to the relay re-enable (cloud).

mediumstores-07
FirestoreStore persists bundles only; kv (sessions, pending_content, hps state) is memory-only on the relay and lost on every scale-to-zero

Persisting kv (sessions/pending/hps) to Firestore needs a real Firestore kv schema + round-trip, unverifiable without cloud and hot-path-risky.

mediumstores-09
Firestore mirror is fire-and-forget on an unbounded queue: 3 quick retries then silent drop, and a degraded Firestore backs the queue up ~45s per op

Bounding/dead-lettering the Firestore mirror queue needs a degraded-Firestore harness to validate backpressure.

lowapple-02
Backgrounded BLE-only iOS device cannot receive: keepalives die on suspend, background adverts invisible to Android, no bg task assertion

Backgrounded BLE-only iOS receive is device-gated: needs Always-location, a real suspended iPhone, and a nearby emitter; not headless-testable.

lowsec-priv-07
Vaccine and its token are cleartext, exposing anonymous-delivery events to any passive observer

Encrypting the Vaccine token is a wire-format redesign with cross-platform decode implications; deferred to a deliberate wire change.

lowservices-02
hop-gateway has no binary, no production HttpClient, and no infra/CI deploy wiring

hop-gateway is an orphaned crate (no binary/consumers); shipping it needs a production HttpClient + infra/CI deploy wiring, or shelve it.
