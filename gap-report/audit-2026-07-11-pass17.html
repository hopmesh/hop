03

Findings

Most-severe first. Each was runtime-verified by a finder; the HIGH/MED in freshly-written code were independently re-verified with fixtures.
F-2 Highrelayd has no panic isolation; one core panic on unauthenticated bytes kills the most exposed processfixed #87
Vector
relayd's apply_event (services/hop-relayd/src/main.rs:595) runs node.handle(BearerEvent::Data) (602), node.ingest (617), node.provide_dns_proof (621), node.tick (699) UNGUARDED on the main thread (driver loop main.rs:887 to driver_step:698). endpoint (guard_core, 20 sites) and gateway (services-r6-01) both wrap exactly these calls in catch_unwind; relayd got neither. A panic on attacker-controlled bundle bytes or a hostile DNSSEC proof unwinds the main thread, the process exits, Cloud Run restarts, the attacker resends: an unauthenticated remote crash-loop DoS on the single most internet-exposed process. HIGH not CRITICAL only because the one known reachable panic (hexd) is patched.
Fix
Mirror endpoint/gateway: wrap the core calls in guard_core (catch_unwind + AssertUnwindSafe), log-and-skip on a caught panic so the node stays live, plus a test that feeds a panicking bundle through apply_event and asserts the driver survives.
F-1 Highdocs guard's Bluetooth / InternetEgress / Wi-Fi Direct bans are case-sensitive; lowercase sails throughfixed this PR
Vector
tools/docs-token-guard.sh:118-127 uses grep -F/-Fw with no -i on the three word bans, while the encoded-dash scan two lines up deliberately adds -i. Proved with fixtures: bluetooth (lowercase), BLUETOOTH, wi-fi direct, internetegress all pass the guard with exit 0. Lowercase is how people naturally type these in prose, so this needs no deliberate evasion to defeat the exact positioning rule the guard exists to enforce.
Fix
Add -i to the three bans; keep the identifier-exclusion patterns (CoreBluetooth, BluetoothAdapter) working; extend the self-test with lowercase + uppercase cases so the gap can never re-open.
F-3 Highcheck-pkg-fresh's drift check is order-dependent and vacuous as wired into CIfixed #91
Vector
Both workflows run sim/build-wasm.sh (overwrites the working-tree sim/pkg from HEAD) immediately BEFORE sim/check-pkg-fresh.sh, whose interface-diff loop then compares a fresh rebuild against that same just-rebuilt copy: it can never detect a stale commit. Proved by editing a real retransmit constant (non-wire) and watching the guard report "fresh". The --committed-only mode built to close this is never invoked anywhere. Mitigated: pages.yml rebuilds sim/pkg for the live deploy, so hopme.sh is not at risk; the exposure is the local toolchain-free build path drifting silently.
Fix
Run check-pkg-fresh.sh --committed-only before build-wasm.sh, or have the diff loop read git show HEAD:sim/pkg/$f so the check stops depending on step order.
F-4 Medthe new encoded-dash scan misses zero-padded HTML entities and the CSS unicode escapefixed this PR
Vector
The encoded-dash scan added in #79 uses fixed strings, so HTML5 zero-padded numeric refs (&#08212;, &#x02014;) and the CSS content:"\2014" form (no u prefix) all render a real em-dash but pass the guard. Verified with fixtures. This is a gap in code written THIS session.
Fix
Broaden to a regex covering optional leading zeros and the bare CSS \2014/\2013 form; add each variant to the self-test.
F-5 Medwasm_glue overstates its coverage; the §39 receiver-beacon is never exercisedfixed #92
Vector
wasm_glue.rs's header claims it is exercised end to end by scenario-check, and the whole file is excluded from tarpaulin on that premise, but grep finds ZERO JS call sites for publish_recv_beacon (the §39 P4 receiver-beacon, a headline privacy feature), send_traced, set_default_lifetime_ms, or inbox_debug.
Fix
Extend a scenario to drive receiver-beacon / traced-send / custom-TTL, or narrow the doc comment to state accurately what the sim does and does not cover.
F-7 Medrelayd has no per-peer / per-node connection or message-rate capfixed #93
Vector
relayd's caps (MAX_CONNS=1024, MAX_FRAME_BYTES=1 MiB) are all GLOBAL, no per-source fairness (unlike the endpoint's accept_peer_limited + XFF rate limit). One hostile node can grab a large share of slots and stream max-size bundles that each force full Noise+parse on the single main-thread driver, CPU-starving other peers and stalling the healthz heartbeat. Memory stays bounded; mitigated by LB + maxScale. The single-driver-thread design also amplifies F-2.
F-6 LowMECHANISMS.md is two wire bumps stale on BUNDLE_VERSION (says 4, actual 6)fixed this PR
Fix
MECHANISMS.md:17 says wire "currently 4"; bundle.rs:46 is 6 (bumped v5 for the r13 recognition-header bind, v6 for the r14 inner bind, both real security fixes). Update to 6.
F-8 LowAstro smartypants (default on) would convert typed -- into a rendered dash, bypassing the guardfixed this PR
Vector
Not exploitable today (web/src has no .md/.mdx, no MDX integration), but a landmine: markdown smartypants converts -- to an en/em dash at render, which the byte-scan guard never sees. Cheap insurance: set markdown:{smartypants:false} in web/astro.config.mjs now.
F-9 LowKotlin HopMessage.hops is signed Byte where the C ABI is uint8_tfixed #91
Vector
sdk/wrappers/kotlin Hop.kt:27 declares hops: Byte though the ABI is uint8_t and the driver bindings use UByte. Not a live bug (hop counts cap at single digits, MAX_RECV_BEACON_HOPS=3), but a type-fidelity gap. Fix: UByte for parity.
F-0 fixedBranch-protection audit was red (403 token scope + wrong context format)fixed (#85)
Vector + fix
The audit workflow granted only contents:read so GITHUB_TOKEN 403'd reading protection, and check-branch-protection.sh expected "CI / job" contexts where GitHub uses raw job names. Added administration:read + corrected the format (verified: expected == the 9 live contexts). Shipped in #85.
