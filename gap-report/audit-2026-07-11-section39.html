The §39 same-id forgery class is closed at the gate, and hop-core reaches A.

§39 is Hop's flagship: untraceable, unsigned, flood-routed private messages. Being unsigned, a private bundle's id is its only integrity check - and a chain of four confirming audits found that the id bound too few fields. A keyless attacker who saw a private bundle flood past could mint a same-id twin with a rewritten recognition header or a flipped scalar; winning the keep-first store race at a chokepoint relay, that twin shadowed the genuine copy and silently denied delivery of the real message. The confirming-audit discipline earned its keep again: hop-core's grade honestly dipped to B when the high-severity relay vector surfaced (pass 13), then climbed to A as four fixes landed - each closing the next residual the prior fix exposed. r13 binds the recognition header into the id; r14 binds the entire private inner; r15 canonicalizes the vaccine. All four are revert-proven, and pass 16 independently confirmed the class is fully closed. Overall quality GPA crossed 3.08 (B); 4 subsystems rose.

03

The §39 same-id forgery class (r12-r15)

One root class - an unsigned, self-verifying bundle id that binds too few fields - took four fix rounds across five confirming audits. Each new vector surfaced only AFTER the prior fix looked complete, and each is closed with a revert-proven test. This is the confirming-audit discipline paying for itself.
r126th vector: recognition-header chimera suppresses delivery✓ closed
Vector + fix
A same-id chimera (rewritten recognition tag) marked store.seen on the flood path; the old gate first = !seen then skipped the genuine copy inbox.push - a silent delivery denial + a false Delivered ACK. Fixed: delivery-once now tracks a delivered_private set (only RECOGNIZED copies enter it), decoupled from flood-dedup seen.
r137th vector (HIGH): the chimera poisons keep-first RELAY stores✓ closed
Vector + fix
r12 only saved a recipient that got a genuine-header copy directly. At a relay (not the recipient) the chimera wins the keep-first store race, occupies the id, re-floods its unrecognizable header, and DROPS the genuine copy - a durable §39 delivery-denial through a chokepoint relay. Fixed at the ROOT: the wire id now binds the recognition header (two-level hash: tag keys on content_id, id binds content_id + header), so a header rewrite yields a different id and verify() rejects a header-inconsistent id at the gate, with no secret.
r14flags.request_ack private twin strips the ACK✓ closed
Vector + fix
r13 bound the header but left the SignedInner SCALAR fields unbound. A keyless twin flipping request_ack -> false kept the id, still self-verified + was recognized, and at a chokepoint relay delivered content but STRIPPED the recipient ACK (sender stranded) + suppressed the vaccine. Fixed: the private wire id now binds the ENTIRE inner (BLAKE3 of the postcard-serialized SignedInner with id zeroed) - header + every scalar - and auto-binds any future field.
r15is_ack vaccine twin defeats epidemic recovery✓ closed
Vector + fix
The delivery vaccine is also unsigned; its id binds ONLY the token (so re-emissions dedup to one flood). A same-id twin with is_ack=false passed verify(), skipped the resolve/drop, and marked the id seen WITHOUT purging - the genuine anti-packet was then deduped out and the delivered bundle re-flooded to TTL. Fixed: verify() now enforces the canonical vaccine shape (is_ack + no src + no payload), rejecting a shape twin at the gate.
r7-r11The traced-ACK / unauthorized-purge class (prior arc)✓ closed
Vector + fix
Five earlier rounds closed the traced-ACK forgery + response-handler purge vectors: authorize (not merely authenticate) an ACK against the acked bundle Device(dst); private => Broadcast at verify (r10); response purges gated on our own outstanding sends (r11). Recapped here as the class this arc extended.

Why the fixes were safe to ship

Every fix in this arc is a verify()-gate tightening or a delivery-dedup decoupling, each landed with a revert-proven test (revert the fix, the guard test fails). No genuine flow regressed - pass 16 re-confirmed create -> recognize -> deliver -> ACK -> vaccine end-to-end.

The honest note The vaccine id still binds only its token (so re-emissions dedup to one flood), leaving created_at / lifetime_ms / priority unbound. A same-id twin flipping those still passes the is_ack gate (so it purges correctly) and carries the same id (so it dedups) - it cannot skip recovery or amplify. Pass 16 rated this an info-level documented tradeoff, no security impact; the grade stays A.
