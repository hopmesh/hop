# libhop architecture — the C-ABI contract + per-bearer isolation

Status as of the `refactor/libhop-bearer-isolation` branch. This is the locked north-star and what's
built/verified toward it. Built autonomously overnight; **nothing is pushed**, the working apps are
**untouched** (the new architecture lives alongside the old until the device-gated cutover).

## The locked decisions

- **One contract, every language.** The bearer seam *and* the full client API are a stable **C ABI**
  exposed by `hop-core` (via `hop-ffi`), header generated by **cbindgen** → `sdk/hop.h`. It's the only
  thing that spans Swift / Kotlin / ObjC / Java / C++ / **ESP32**. UniFFI stays as *optional* mobile
  sugar over the same `HopNode`.
- **libhop is the universal floor.** Not just the bearer seam — the whole client API. An ESP32 can be
  a *full* client (make a node, secure sessions, POST to a `hops://` service), not just a bearer host.
- **1 completely isolated lib per bearer.** Each transport is its own package/module depending only on
  the SDK; the BLE lib owns its beacon/CoreLocation wake + GATT-data fallback. No route is ever
  deleted ("the network that finds a way" — more bearers the better).
- **Two messaging modes, kept distinct.** `hop_send_message` = an **HDP datagram** (the only response
  is the network delivery-ACK). `hops://` = **request/response** (`hop_send_service_request` +
  `hop_poll_service_responses`), HDP in both directions.
- **Poll model preserved** (no UniFFI callbacks for the seam): the platform feeds events in and drains
  outbound out, by `LinkId` + `HopLinkRole`. Nothing transport-specific crosses the contract.

## North-star repo layout

```
core/      hop-core (protocol) + hop-ffi (→ libhop/hop.h via cbindgen, + optional uniffi) + stores
sdk/       hop.h (published) + wrappers/{swift,kotlin,...} — thin idiomatic faces, generated-contract
bearers/   <platform>/<bearer> — one ISOLATED lib each, binds the seam (apple done; android/esp32 next)
drivers/   <platform> — thin: wraps libhop + registers bearers
apps/      <platform> + esp32 + labs — thin consumers
services/  hop-relay/relayd/gateway/endpoint     tools/  testkit/codegen     web/  docs/  infra/
```
(Today the Rust crates still live in `crates/` and the old Apple `HopBearers`/`HopDriver` still build
the shipping app. The `git mv` migration into this tree is a tracked morning task — see below.)

## What's BUILT and VERIFIED

The whole spine is proven end to end, **four languages against one generated header**:

| Layer | Where | Proof |
|---|---|---|
| C ABI | `crates/hop-ffi/src/cabi.rs` → `sdk/hop.h` | `examples/smoke.c`: real §39 send→deliver+ACK, base58, **hops:// round-trip** |
| Swift SDK | `sdk/wrappers/swift` (`Hop`) | `HopSmoke` (wrapper) + `RuntimeSmoke` (HopRuntime + a Bearer drive the node) |
| Kotlin SDK | `sdk/wrappers/kotlin` (`sh.hop`, JNA) | `Smoke.kt`: §39 send→deliver+ACK + base58 on the JVM |
| ESP32 client | `apps/esp32/hop-sensor` | pure-C full client POSTs weather to a `hops://` service, reads the ack |
| Bearers (Apple) | `bearers/apple/HopBearer{Ble,Lan,Multipeer,Relay}` | each an independent SwiftPM package, `swift build` clean |

Run it all: `crates/hop-ffi/examples/smoke.sh`, `sdk/wrappers/swift/smoke.sh`,
`sdk/wrappers/kotlin/smoke.sh`, `apps/esp32/hop-sensor/build.sh`. Rust: `cargo test` (128 + crates green).

**The Swift bearer stack is functionally proven**: `RuntimeSmoke` registers a `Bearer` with
`HopRuntime` and runs the real protocol — the four real radios conform to the same `Bearer` protocol,
so they behave identically once wired to hardware.

   the old `apple/HopBearers` + the in-driver legacy (`HopLink`/`GattDataLink`). Needs an **xcframework

   (`bearer-ble/lan/wifidirect/relay`) onto the Kotlin SDK as isolated gradle modules; delete the
   ~2200-line `HopBearer.kt` god-object **and the stale `F0900BEA` beacon UUID** (use `7ED7BEAC`);
   wire the app. Needs the Android toolchain + device verification.
3. **Tree migration** — `git mv` `crates/`→`core/`+`services/`, etc., into the layout above; update the
   Cargo workspace + package paths; keep every build green. Mechanical but touches the shipping build,
   so do it with builds running.
4. **Full client API** — expand the C ABI as needed (peers list, queue, hps channels, HTTP-over-hops,
   identity rotation). The pattern is set; add along the way.
5. **CI guardrail** — a lint that fails if any transport symbol (CBUUID/BluetoothGatt/CLBeaconRegion/…)
   appears in the SDK contract or `hop-ffi` C-ABI surface.

## How to extend

- **New bearer**: make a package/module that conforms to `Bearer` (Swift) / implements the same
  contract (Kotlin), depend only on the SDK, register it with `HopRuntime`/`BearerManager`. Touches
  nothing else.
- **New language**: bind `sdk/hop.h` (it's plain C) + add a thin idiomatic wrapper under
  `sdk/wrappers/<lang>`. The Swift/Kotlin wrappers are the template.
- **New client platform** (embedded, desktop, …): link `libhop` + use `hop.h`. See `apps/esp32/hop-sensor`.
